# Start

Run these steps once, in order, when no `state.md` exists for this work. `<dir>` is the supervisor folder; "the reference" is
`references/monitoring-and-operator-gate.md`. After a compaction in the middle of Start,
Resume in SKILL.md sends you back here for the steps that still have a `TBD` in Config.

1. Check `test "${HERDR_ENV:-}" = 1`. If it fails, tell the operator this skill needs Herdr and stop.
2. Check that `ListAgents` works. If it does not, tell the operator and stop.
3. Find this session's name in the `ListAgents` listing. If you cannot tell which entry is this session, or the name is generic, ask the operator to `/rename` it to a specific name, because briefs address replies to it.
4. Resolve four absolute paths and check each with `test -x`: `pending-watch.sh` and `supervisor-check.sh` in this skill's `scripts/` folder, and `create-session.sh` and `stop-session.sh` in the `scripts/` folder of the installed `managed-session` skill. If one is missing, tell the operator and stop.
5. Read `references/role-skill-map.md`. For each skill in its Skill column, check that `<project>/.claude/skills/<skill>/SKILL.md` or `~/.claude/skills/<skill>/SKILL.md` exists. For each one missing, tell the operator in one line; that role is dispatched with the brief alone, without a slash command.
6. Read the source fully with the docs it names, and decide its shape (see "Shape of the work" in SKILL.md). Note the main branch and its head (`git log --oneline -1 <main>`), the operator's language and the timezone. Find the test command in the project docs and run it once on main for the baseline count; if you find none, or it needs live credentials or costs money, ask the operator in step 14 instead of guessing.
7. Create the supervisor folder in the project, named by the repo's plan convention (e.g. `plans/261116-0910-<slug>-supervisor/`), with `briefs/`, `reports/`, `questions/`, `follow-ups.md`, and `sessions.md` (one row per session: name, pane ID, skill, model, brief, status, result commit). Status is `running` or `stopped`, plus notes the reference asks for, such as "report requested". Never use the scratchpad; its files are deleted after a few days.
8. Run `supervisor-check.sh setup <dir> --repo <project path> --main <main branch> --test '<test command>'` (leave out `--test` when step 6 found none, and run `setup` again with it once the operator answers). It saves the main head as the verified head and the `git status --porcelain` baseline: files already modified or untracked before you start are the operator's, not a worker's. Then write `<dir>/state.md` with the Write tool, in three parts:
   - Config: source path and shape; this session's name; the main branch, test command with its baseline count, operator language and timezone from step 6; the four script paths from step 4; worker model per tier and maximum parallel sessions (step 14); the project's post-merge steps (step 13 or 14); the loop prompt (step 16); the loop state ("loop: running" or "loop: paused"). Write `TBD` only for the values a later step settles.
   - Items: one row per milestone or phase not yet done, with what it depends on, the operator gate it needs, status (including `failed rounds: <n>` and the `D<n>` that blocks it), and the commit that made it done.
   - Decisions: one line per decision with date and time, who decided (supervisor, or operator with the `D<n>`), the decision, and what it covers. Operator delegations and their scope go here. Record each missing skill from step 5 here too.

   Update `state.md` after every verified report and every decision. Only the ledger is script-only; write `state.md` with Write or Edit.
9. Run `pending-watch.sh init <dir> --session <this session's name>`. It creates the live ledger `~/supervisor/<project>--<session>.md`, where the operator answers every project's questions, and writes its path to `<dir>/ledger.path`. Do not create a `pending-decisions.md` in the project. If `init` cannot write `~/supervisor`, run `/add-dir ~/supervisor`, or ask the operator to run `~/personal/head-chief/install.sh --sync-settings`; a running session picks up the new access without a restart.
10. Start `pending-watch.sh watch <dir>` with `run_in_background`. It calls no model: it badges this Herdr tab `⏳N`, sends notifications, and exits when the operator edits the ledger, which wakes you. Its PID is in `<dir>/.pending-state/pid`; do not track it in `sessions.md`.
11. If the watcher says `terminal-notifier` is not found, tell the operator once that `brew install terminal-notifier` adds desktop notifications that open the ledger when clicked.
12. Read `references/monitoring-and-operator-gate.md` in full.
13. Look for the project's post-merge steps in its CLAUDE.md, AGENTS.md or contributor docs, and record them in `state.md` Config.
14. Ask the operator through the operator gate (SKILL.md), one ledger item per decision, skipping a decision that already has an OPEN item in `pending-watch.sh list <dir>` (record its answer instead of asking again): which model workers use for each tier, strongest, default and cheaper (see "Model tier for a task" in `references/role-skill-map.md`; you choose the tier per task, the operator chooses the models), how many sessions may run in parallel (recommend 3), the post-merge steps if step 13 found none, and the test command if step 6 found none. Record the answers in Config. When the test command is answered, also run `supervisor-check.sh setup <dir> --repo <project path> --main <main branch> --test '<test command>'`, or `accept` keeps skipping the tests. If an answer has not come yet, do step 15, write the loop prompt into Config (step 16), then pause as "Stopping the loop" in the reference says: write "loop: paused" in Config, stop the loop if it is running, and end the turn. The watcher's exit or the operator's chat message wakes you. Open no session while a model or the cap is `TBD`, and do not run `close`.
15. Tell the operator, in their language, the order you will run and the gates that need them.
16. Write the loop prompt into Config: the operator's request, then "Supervisor folder: <abs dir>. Follow the Resume section of the roadmap-supervisor skill: read <abs dir>/state.md and rebuild state before acting." Then make sure the loop runs, per the "Loop cadence" section of the reference:
    - If the operator started this conversation with `/loop`, the loop already runs. Pass the loop prompt as `prompt` on every `ScheduleWakeup` call.
    - Otherwise read the `loop` skill's description and invoke it with the loop prompt and no interval. If you then cannot call `ScheduleWakeup`, ask the operator to type `/loop <loop prompt>`.
17. Once Config has no `TBD` left, start the first session (see "Briefs and dispatch" in SKILL.md).
